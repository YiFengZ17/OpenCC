# Credit 结算接入进度

2026-10-25。本文件不包含任何账户密码或登录令牌。

## 已实现（未启用）

- `internal/creditbilling`：服务端读取 SuperGPT `/api/v1/usage`，按页检查结果，严格核对上游请求编号、密钥 ID、分组 ID、模型。凭证通过运行时回调提供，不写入源码；拒绝重定向，避免向其他地址转发凭证。
- 实际 credit 字段名和请求编号字段名必须配置为已核实的响应字段，不猜字段，不从金额倒推用量。
- 只接受 `kiro_credit` 完成状态；`kiro_credit_missing` 与 `kiro_credit_error` 继续等待。找不到、重复匹配、响应格式变化均不产生扣款命令。
- 使用 decimal 计算人民币费用，保留八位小数，不额外叠加 Token/模型倍率。
- `CreditSettlementService`：持久化对账队列、领取任务租约、重试、人工核对状态。先冻结扣费命令，再调用原有幂等账本，服务重启后重复执行同一命令不重复扣款。成本和售价分别保存。
- 新增迁移 `247_opencc_credit_settlements.sql`，尚未在生产数据库执行。
- 解析、安全边界、金额精度、扣费命令稳定性单元测试通过；尚无真实 PostgreSQL 事务集成验收。

## 当前接入阻碍

直接登录收到 Turnstile 验证失败。用户已在 Edge 登录；浏览器扩展返回 Debugger unattached，尚无法读取认证后的真实账单。不能确认 credit 字段、分页响应格式、上游 HTTP 请求 ID 与账单 request_id 的对应关系。

## 启用前必须继续完成

1. 读取一条已结算 credit 账单，核对字段、模型名口径、单次请求对应关系。确认控制台认证刷新方法和查询频率。
2. 接入网关请求前的持久化额度预留和并发限制；转发后持久化请求关联，禁用此分组原 Token 扣费路径。失败和断连需保留待核对记录，不能推断为免费。
3. 注册后台结算 worker，接入余额/密钥/平台额度缓存失效、原生用量行更新，以及预留额度释放。
4. 添加用户账单明细和管理员待核对入口；核对跨用户权限。
5. PostgreSQL 集成测试：并发领取、余额不足、查询延迟、重复记录、扣费成功但写状态前崩溃、原生账本幂等重放。
6. 完成真实小额联调后才启用。当前服务未注册到 Wire，也没有网关调用入口，不会产生真实扣款。

前端仍然显示待接入。这份代码是接入中的后端模块，不能当作完整上线版本。
