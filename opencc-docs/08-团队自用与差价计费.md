# 团队自用与差价计费

更新：2026-10-26。

OpenCC 作为团队内部工具使用：成员由管理员开通，余额以人民币计价（1 记账单位 = ¥1），按高于上游成本的价格扣费，差额即毛利。

## 计费模型

每次请求，网关根据上游返回的 usage（input / output / cache Token 数）计算：

| 名称 | 公式 | 记录位置 |
|---|---|---|
| 标准费用 | Token 数 × 模型基础单价（渠道定价） | `usage_logs.total_cost` |
| 用户实扣 | 标准费用 × 分组倍率 **D** | `usage_logs.actual_cost`，从成员余额扣除 |
| 上游成本 | 标准费用 × 账号倍率 **U** | `account_rate_multiplier` 快照，后台“账号成本” |
| 毛利 | 用户实扣 − 上游成本 = 标准费用 × (D − U) | 后台仪表盘“毛利” |

所有金额都是人民币。后台部分旧页面仍显示 `$` 符号，那只是原项目的记账符号，数值即人民币。仪表盘已改为 ¥ 并新增毛利一行。

## U：上游成本倍率

U 必须表示“每 1 单位标准费用，你实际花多少人民币”：

```
U = 上游分组倍率 × (你向上游充值 ¥X 得到的额度 $1 时的 X)
```

- 上游充值 ¥1 = $1 额度，且分组倍率 0.15 → U = 0.15。
- 上游充值 ¥0.8 = $1 额度，分组倍率 0.15 → U = 0.12。

**自动同步**：若上游也是 Sub2API（SuperGPT 控制台接口与 Sub2API 一致），账号可开启“上游计费探测”与“倍率同步”，网关每 30 分钟读取上游 `/v1/sub2api/billing`，把上游分组倍率写入 U。它只同步倍率，不知道你的充值比例；只有在上游充值比例为 ¥1 = $1 时才能开启倍率同步，否则关闭同步、按上式手工填写 U。

## D：成员售价倍率

```
D = U × (1 + 加价率)
```

例：U = 0.15，加价 20% → D = 0.18。Claude Sonnet 基础价输入 $3 / 输出 $15 每百万 Token，成员看到的价格为 ¥0.54 / ¥2.7 每百万 Token；每百万输入 Token 毛利 ¥0.09。

D 在“分组”中设置；也可以对单个成员设置覆盖倍率。OpenAI / Grok 分组可开启“利润控制”，当某账号 U 高于 D × (1 − 最低毛利率 − 安全缓冲) 时不调度该账号，防止上游涨价后亏本；Anthropic 分组没有该开关，需要人工核对。

## 后台配置步骤

1. **账号**：新建 API Key 账号，Base URL 填上游地址，Key 只填在服务端。设置 U，或按上一节开启探测和倍率同步。
2. **分组**：新建分组（例如 `claude-team`），倍率填 D；把账号加入分组。
3. **渠道**：新建渠道并绑定该分组，填写模型和基础单价（与上游公开基础价一致，不要填已乘倍率的价格）。模型广场与 `/pricing` 只显示渠道里配置的模型。
4. **设置**：打开“模型广场”；关闭公开注册，或开启邀请码注册，只发给团队成员。
5. **成员余额**：二选一
   - 用户管理 → 调整余额（加 ¥N，备注收款记录）；
   - 生成余额类型兑换码（面值即人民币）发给成员，在“账户充值”兑换。外部发卡平台和 `OPENCC_SHOP_*` 链接可以不配置。
6. **核对**：用一个成员密钥发一次小请求，在后台“使用记录”核对 `actual_cost = total_cost × D`、账号成本 = `total_cost × U`，仪表盘毛利为二者之差。

## 上游价格快照

`opencc-docs/reference/upstream-pricing-2026-10-24.json` 是 2026-10-24 抓取的上游公开价格，仅供管理员填写渠道单价时参考。它是采购成本，已从前端移除，不会再展示给成员。

## 备份

`deploy/opencc-backup.sh` 用 `pg_dump` 导出数据库到 `deploy/backups/`，默认保留 14 天。建议加入 crontab（脚本头部有示例），并定期把备份拷到 VPS 以外的位置。
