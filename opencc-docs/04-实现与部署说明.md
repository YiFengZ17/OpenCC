# OpenCC 实现与部署说明

更新：2026-10-24。源码目录：仓库根目录。

## 本地运行

```bash
cd frontend
corepack pnpm@10.11.0 install --frozen-lockfile
corepack pnpm@10.11.0 dev:opencc
```

打开 `http://127.0.0.1:3180/home`。预览使用独立的本地演示数据，页面有明确标记。演示卡密 `OPENCC-DEMO-10` 可兑换一次 10 积分；重启演示服务会重置。演示环境禁止向真实模型转发；ModelTrace 可用手动粘贴模式验证计算流程。

正常开发使用 `pnpm dev`，通过 `VITE_DEV_PROXY_TARGET` 连接真实后端。生产构建使用 `pnpm build`，演示中间件和演示登录不会被打进生产网页。

## 已实现页面

| 路径 | 内容 |
|---|---|
| `/home` | OpenCC 首页、模型入口、接入指南 |
| `/dashboard` | 可用积分、今日用量、密钥数、最近调用 |
| `/model-plaza` | 模型列表、系列筛选、搜索、复制模型 ID |
| `/pricing` | 上游价格快照／本站配置价格，人民币积分单位 |
| `/keys` | 创建密钥、分组、积分限额、复制、停用、删除 |
| `/usage` | 调用明细、模型筛选、分页、实际积分消耗 |
| `/model-test` | ModelTrace 自动检测、手动检测、请求进度、报告下载 |

登录、注册、账户设置和管理员控制台沿用 Sub2API 的鉴权与管理能力。后台原有支付功能保留但本期不启用，用户侧不提供在线支付或退款入口。

## 上线顺序

1. 检查服务器已有服务、端口、磁盘和 Caddy 配置。备份现有 Caddyfile。不要停止 `proxy.opencc.app`。
2. 将仓库源码放在独立目录，例如 `/opt/opencc-web/app`。保留 LICENSE 与 ModelTrace 的 LICENSE。
3. 在 `deploy` 复制 `.env.opencc.example` 为 `.env.opencc`，填写管理员、数据库和签名密钥，权限设为 `600`。不要提交或发到聊天。
4. 先执行 `docker compose --env-file .env.opencc -f compose.opencc.yml config --quiet`。没有真实参数时，该命令应拒绝启动。
5. 执行 `docker compose --env-file .env.opencc -f compose.opencc.yml up -d --build`。检查 `/health` 和三个服务状态。
6. 将 `Caddyfile.opencc` 的站点块合并到现有 Caddy 配置。如果已经有 `opencc.app`，合并现有块，不重复定义。先运行 Caddy validate，通过后 reload；保留旧配置以便回滚。
7. Cloudflare 的 `opencc.app` A 记录指向这台 VPS，使用代理模式；TLS 配置采用 Full (strict)。API 路径 `/api/*`、`/v1/*`、`/setup/*` 禁用缓存，开启 IP Geolocation。上线前核对实际配置。
8. 首次登录后台需由运营者本人阅读并逐字确认 Sub2API 合规承诺（`docs/legal/admin-compliance.zh.md`），否则后台接口返回 423。然后设置站名 OpenCC、打开模型广场、关闭公开注册或启用邀请码、公告、支持联系方式。
9. 按 `08-团队自用与差价计费.md` 配置账号（U）、分组（D）、渠道（模型与基础单价）和成员余额，跑一笔小额请求核对实扣、账号成本与毛利；再用这把密钥进行 ModelTrace 自动检测。
10. 配置 `deploy/opencc-backup.sh` 定时备份。
11. 检查不同地区下的提示、移动端、账户隔离、限额、余额不足和重复兑换后，再开放销售。

回滚：恢复旧 Caddy 站点配置并 reload；停止 `opencc-web` 的 app 服务。不要删除数据库卷，升级前另做数据库备份。

## 接口边界

- `GET /api/v1/opencc/config`：公开站点配置，只有购买链接、支持地址、显示换算等非敏感信息。
- `GET /api/v1/opencc/region`：返回是否显示地区提示。只信任配置中的直接反代来源，并要求反代清理伪造地区头；无可信地区信息时不显示。响应为 `private, no-store`，不返回 IP。
- 原有登录鉴权保护 `/keys`、`/usage`、`/redeem`、`/redeem/history` 等接口。前端不会自行修改用户余额。
- ModelTrace 使用用户选择的本站密钥，请求本站 `/v1/messages`、`/v1/chat/completions` 或 `/v1/responses`；不接收任意外部 URL，不将密钥发给 ModelTrace 项目方。
- 卡密购买平台负责收款、发卡。未收到其 API 文档前，不编造回调签名或自动到账协议。当前通过真实卡密兑换完成到账。

## 地区提示

按用户指定文案实现，仅可信国家码为 CN 时显示；其他地区及未知地区隐藏。该功能是界面提示，不等同于模型授权控制。提示中的“不存储信息”尚不代表整套系统的存储事实：账户、兑换、用量记录依旧由原系统保存。请求正文记录需在上线时核对并关闭不需要的采集功能。
