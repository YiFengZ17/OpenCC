# 模型检测与积分计费

更新：2026-10-24。

## ModelTrace 接入

来源：https://github.com/xqy2006/ModelTrace

固定提交：`6cd4a8ff0f3f4e49d6d6969dd2fbadfa1569fde2`。采用 MIT 许可，许可证、来源和版本保留在 `frontend/src/opencc/vendor/modeltrace`。上游算法、挑战生成器和统一指纹库保持原样；OpenCC 添加 Vue 页面及本站 API 调用适配器。

自动检测流程：选择已登录账户的有效 API 密钥 → 填写模型 ID 与协议 → 确认消耗说明 → 顺序发出三次独立请求 → 检查截断及有效数字 → 在浏览器计算归因 → 展示候选概率和请求记录 → 可下载 JSON 报告。

支持 Anthropic Messages、OpenAI Chat Completions、OpenAI Responses。每次请求输出上限 4096 Tokens、超时 120 秒；可以取消。已发出的请求可能依然扣费。密钥只存在当前页面和发往本站网关的认证头中，不写入检测报告。

手动模式保留三条独立挑战及输出粘贴框。该模式不能验证粘贴内容来自哪个 API，报告会明确标记为手动输入。

目前库内 18 个型号，分属 Claude 和 GPT；Grok 无参考指纹。相似度和概率是当前候选库内的统计结果，不是“纯度百分比”。未收录模型可能被归到已有候选，所以页面不为未收录型号给出版本通过结论。输出不足三份时也不通过。型号一致不能证明全部历史或未来请求的来源。

## 价格政策

> 2026-10-26 更新：改为团队自用并加价，售价倍率 D 高于上游成本倍率 U，见 `11-团队自用与差价计费.md`。本节其余内容（单位、倍率不重复相乘）仍适用。

用户于 2026-10-24 确认：保留上游价格数值，美元符号对应人民币价格单位。不是外汇换算。

- 充值：10 元卡密 → 10 积分；50 元 → 50 积分；100 元 → 100 积分；200 元 → 200 积分。
- 1 个内部余额记账单位 = 1 人民币积分。`OPENCC_CNY_PER_CREDIT=1`，发卡后不要随意改变。
- 上游标价 $1 的数值，在本站按 1 积分展示和配置。上游金额可能已含分组倍率，要避免重复乘倍率。
- 示例：渠道输入单价为 0.000002 / Token，分组倍率为 0.15，则本站标准输入价格为 `0.000002 × 0.15 × 1,000,000 = 0.3 积分 / 百万 Tokens`。
- 图片／按次价格保留每张／每次单位，不乘百万；图片独立倍率、长上下文档位、时段倍率及推理强度倍率单独保留。空值表示未知，0 才表示零价。

价格快照来自 `https://console.supergpt.dev/api/v1/model-plaza`，抓取日期 2026-10-24。文件为 `opencc-docs/reference/upstream-pricing-2026-10-24.json`，仅供管理员参考。`/pricing` 只展示本站渠道配置的价格，不再回退到上游快照，避免向成员暴露采购成本。

后台配置时：按照快照建立对应分组和渠道，将基础单价及倍率分别填写。不要把已经乘过倍率的最终单价再配同一倍率。卡密类型采用余额类型（balance），卡密 value 为 10、50、100、200。旧后台部分字段仍可能标 USD，那是原项目的记账标签，本项目的人民币积分政策另行定义。启用销售前用一个小额调用核对实际扣分与页面价格一致。

若供应商以后仅提供 credit 报价，必须取得 credit 的实际充值金额与数量，用“实际付费数值 / credit 数量”换算并注明来源；本次公开价目已提供美元价格，无需虚构 credit 汇率。

## 卡密闭环

1. 管理后台批量生成余额卡密（value 按积分面额）。
2. 将卡密库存导入发卡平台相应商品；商品面额与卡密积分一致。
3. 用户在发卡平台付款并取得卡密。
4. 用户登录 OpenCC，在“积分充值”输入卡密。
5. 后端校验和核销后增加余额；前端重新读取账户余额。
6. 用户在“兑换记录”查询到账积分与时间。重复核销由后端拒绝。

目前没有接入第三方支付回调。未来若需自动供卡，另按平台公开 API 实现签名验证、金额验证及订单幂等，不以浏览器跳转结果作为到账凭据。
