# 团队自用与差价计费

更新：2026-10-26。

OpenCC 作为团队内部工具使用：成员由管理员开通，余额以人民币计价（1 记账单位 = ¥1），按高于上游成本的价格扣费，差额即毛利。

## 计费模型

每次请求，网关根据上游返回的 usage（input / output / cache Token 数）计算：

| 名称 | 公式 | 记录位置 |
|---|---|---|
| 标准费用 | Token 数 × 模型基础单价（渠道定价） | `usage_logs.total_cost` |
| 用户实扣 | 标准费用 × 分组倍率 **D** | `usage_logs.actual_cost`，从成员余额扣除 |
| 上游成本 | 标准费用 × 账号倍率 **U** | `account_rate_multiplier` 快照，后台“账号成本” |
| 毛利 | 用户实扣 − 上游成本 = 标准费用 × (D − U) | 后台仪表盘“毛利” |

所有金额都是人民币。后台部分旧页面仍显示 `$` 符号，那只是原项目的记账符号，数值即人民币。仪表盘已改为 ¥ 并新增毛利一行。

## U：上游成本倍率

U 表示“每 ¥1 标准费用，上游实际扣你多少人民币”。上游的 $1 额度就是 ¥1（2026-10-26 确认），所以 U 理论上等于上游分组倍率。

但上游 Claude 分组“claude 满血kiro”不是 Token 倍率计费：结构化接口为 `credit_billing.enabled=true, unit_price=0.095`（¥0.095 / credit，见 `08-分组与credit核对.md`），credit 与 Token 数没有固定换算，标称的 0.8 倍率不适用。因此：

- Token 计费分组（GPT、Grok）：U = 上游分组倍率，可开启探测与倍率同步。
- Claude credit 分组：**不要开启倍率同步**，也不能用单一 U 准确计费。按 `08` / `10` 文档的结论，逐笔 credit 结算接入完成前不开放售卖。
- 结算接入前若要在团队内部试用，可用下文的 `measure` / `reconcile` 测出真实成本与本站标准费用的比值，按偏高的 U 设置，并持续对账；这只是近似，不等同于逐笔 credit 结算。

## D：成员售价倍率与自定义模型组

分组完全由本站定义，和上游分组无关；多个本站分组可以共用同一个上游账号。可以按需要建多个 Claude 分组，例如：

| 本站分组 | 渠道里放的模型 | 用途 |
|---|---|---|
| `claude-sonnet` | Sonnet、Haiku 各版本 | 日常编程，倍率较低 |
| `claude-opus` | Opus 各版本 | 复杂任务，可设更高倍率或只给部分成员 |

每个分组建一个渠道，只列出该组允许的模型，并开启“限制模型”，成员用这个分组的密钥就只能调这些模型。需要别名时用渠道的模型映射（例如把 `claude-sonnet` 映射到具体版本）。

定价公式：

```
D = U ÷ (1 − 目标毛利率)
```

| U | 毛利 15% | 毛利 25% | 毛利 35% |
|---|---|---|---|
| 0.22（ChatGPT-Pro 稳定） | 0.26 | 0.29 | 0.34 |
| 0.25（ChatGPT-Pro 企业） | 0.29 | 0.33 | 0.38 |
| 0.36（ChatGPT-ProMax 企业） | 0.42 | 0.48 | 0.55 |
| 0.9（假设值，Claude 需实测） | 1.06 | 1.20 | 1.38 |

D 在“分组”中设置；也可以给单个成员设置覆盖倍率。OpenAI / Grok 分组可开启“利润控制”，U 超过 D × (1 − 最低毛利率 − 安全缓冲) 时自动停用该账号；Anthropic 分组没有这个开关，需要靠下面的对账发现亏损。

## 测量真实成本

`deploy/opencc-cost-check.py` 读取上游 `/v1/usage` 返回的余额（上游是 Sub2API 时提供），用“余额减少量 ÷ 本站标准费用”得到真实 U。上游地址和 Key 只从环境变量读取：

```bash
cd /opt/opencc-web/app/deploy
export OPENCC_UPSTREAM_BASE=https://api.supergpt.dev
read -rs OPENCC_UPSTREAM_KEY && export OPENCC_UPSTREAM_KEY   # 粘贴 Key，不进 shell 历史
```

**主动测量（上线前）**：对每个模型发短、长两种请求各 2 次，花费约几毛钱。最好用一把单独的上游 Key，避免其他流量干扰余额。

```bash
python3 opencc-cost-check.py measure --model claude-sonnet-4-5 --model claude-opus-4-6
```

输出把上游扣费拆成 `a × 标准费用 + b（每次固定费用）`，并给出不同请求大小下的真实 U 和对应 D。b 明显大于 0 说明有按次费用，小请求成本更高。

**持续对账（上线后）**：每小时比较上游余额减少量和本站记录的标准费用、成员实扣、账号成本，输出真实 U 与真实毛利；记录的成本与真实花费相差超过 5% 时提示应把账号倍率改成多少。上游余额上升（充值）的时段自动跳过。

```bash
# deploy/cost-check.env（chmod 600，已在 .gitignore）：
#   export OPENCC_UPSTREAM_BASE=https://api.supergpt.dev
#   export OPENCC_UPSTREAM_KEY=...
# crontab，账号 ID 在后台“账号”列表查看：
7 * * * * cd /opt/opencc-web/app/deploy && . ./cost-check.env && ./opencc-cost-check.py reconcile --account-id 1 >> backups/cost-check.log 2>&1
```

### 操作流程（需要你本人操作）

测量用的是**上游 SuperGPT 的 API Key**（不是本站成员密钥），需要在一台能访问 `api.supergpt.dev` 的机器上运行：VPS 或你自己的电脑（WSL 也可以），只需要 Python 3，不用安装依赖。

1. 在 SuperGPT 控制台新建一把 Key，选 Claude 分组，余额留 ¥1 左右即可。这把 Key 只用来测量，测完可以删除或留作对账。
2. 运行测量（Key 用 `read -rs` 输入，不写进命令行和 shell 历史）：
   ```bash
   cd OpenCC/deploy
   export OPENCC_UPSTREAM_BASE=https://api.supergpt.dev
   read -rs OPENCC_UPSTREAM_KEY && export OPENCC_UPSTREAM_KEY
   python3 opencc-cost-check.py measure \
     --prices ../opencc-docs/reference/upstream-pricing-2026-10-24.json \
     --model claude-sonnet-4-6 --model claude-opus-4-6 --model claude-haiku-4-5
   ```
   本站上线并配置好渠道后，可以去掉 `--prices`，默认读取本站价格。测量期间不要用这把 Key 做其他事情。
3. 看输出的四部分：
   - **上游响应头**：如果出现带 cost / credit / quota 字样的字段，说明上游每次请求都返回费用，告诉我，可以改为逐条记录真实成本。
   - **每次请求**：标准费用、余额减少量、U。
   - **整体**：本站标准费用、上游自己记录的标准费用和扣费、余额减少量。前两者不一致 → 渠道基础单价填错；扣费小于余额减少量 → 积分计费有未体现在用量记录里的额外费用。
   - **每个模型**：`a`（按 Token 的倍率）和 `b`（每次固定费用），以及不同请求大小下的建议 D。
4. 后台把账号倍率 U 设为团队常见请求大小对应的值，再按上文表格设置各分组 D。
5. 上线后配置每小时 `reconcile`，用真实流量持续核对，按提示修正 U。

如果希望由 Claude 代为运行测量：在云端环境设置里允许访问 `api.supergpt.dev`，并把这把测量用 Key 存为环境密钥 `OPENCC_UPSTREAM_KEY`（不要发在聊天里），新会话即可读取。

本地用模拟上游（标准费用 × 0.8 + 每次 ¥0.002）验证：measure 准确还原 a = 0.800、b = ¥0.002，并通过“上游记录扣费 < 余额减少量”识别出未记录的按次费用；reconcile 与手算一致，并在售价低于真实成本时给出警告。

## 后台配置步骤

1. **账号**：新建 API Key 账号，Base URL 填上游地址，Key 只填在服务端。Token 计费分组的账号倍率填 U 或开启倍率同步；Claude credit 分组见上文，不开同步。
2. **分组**：按上表新建本站分组，倍率填 D；把账号加入分组。
3. **渠道**：每个分组一个渠道，填写模型和基础单价（与上游公开基础价一致，不要填已乘倍率的价格），开启“限制模型”。模型广场与 `/pricing` 只显示渠道里配置的模型。
4. **设置**：打开“模型广场”；关闭公开注册，或开启邀请码注册，只发给团队成员。
5. **成员余额**：二选一
   - 用户管理 → 调整余额（加 ¥N，备注收款记录）；
   - 生成余额类型兑换码（面值即人民币）发给成员，在“账户充值”兑换。外部发卡平台和 `OPENCC_SHOP_*` 链接可以不配置。
6. **测量**：运行 `opencc-cost-check.py measure`，按结果修正 U 和 D，并配置每小时 `reconcile`。
7. **核对**：用一个成员密钥发一次小请求，在后台“使用记录”核对 `actual_cost = total_cost × D`、账号成本 = `total_cost × U`，仪表盘毛利为二者之差。

## 上游价格快照

`opencc-docs/reference/upstream-pricing-2026-10-24.json` 是 2026-10-24 抓取的上游公开价格，仅供管理员填写渠道单价时参考。它是采购成本，已从前端移除，不会再展示给成员。

## 备份

`deploy/opencc-backup.sh` 用 `pg_dump` 导出数据库到 `deploy/backups/`，默认保留 14 天。建议加入 crontab（脚本头部有示例），并定期把备份拷到 VPS 以外的位置。
